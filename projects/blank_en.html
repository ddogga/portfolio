  • 클라이언트가 조작 가능한 쿠키 값을 그대로 Java 역질렬화 하던 보안 취약점을 제거

  • flyway 기반 마이그레이션 환경 구축해 RDS 수동 작업 없이 로컬, 운영간 동일 스키마 재현

문제 상황

소셜 로그인을 세션 방식으로 구현한 뒤, 서버 세션 없이 인증 상태를 유지하는 JWT 기반 STATELESS 구조로 전환하였다. 그런데 보안상 두 가지 문제점이 생겼다.

1. 서버가 인증 상태를 통제할 수단이 사라졌다. JWT는 서명만으로 검증되므로 한 번 발급하면 만료 전까지 서버가 무효화 할 수 없다. 또한 토큰에 담긴 역할(role)도 만료 전까지 바뀌지 않는다. 토큰 하나로 관리하게 되면 수명을 길게 잡을 수록 탈취 시 피해가 커지고, 짧게 잡으면 사용자가 자주 재로그인해야 하는 상황이었다.

2. OAuth2인가 요청 정보를 보관할 안전한 저장소가 사라졌다. 로그인 시작 요청과 제공자 콜백 요청은 별개의 HTTP 요청이므로 콜백에서 시작 요청시 받은 state 값을 검증해야 한다. 따라서 시작 시점의 인가 요청을 어딘가에 보관해 두어야 하는데 Spiring Security의 기본 저장소는 HttpSession이라 STATELESS 구조와 맞지 않았다. 이를 대신하기 위해 인가 요청 객체를 Java 직렬화 쿠키에 담는 방식을 먼저 적용했다. 그런데 이 방식은 클라이언트가 입의로 조작할 수 있어 서버에서 그대로 역질렬화시 조작된 정보를 다룰 위험성이 존재했다.

분석

첫번째 토큰 문제는 "매 요청 빠르게 검증되어야 한다"는 요구와 "서버가 통제할 수 있어야 한다"는 요구가 충돌하는 것이었다. 두 요구를 한 토큰에 담지 않고 역할을 나누기로 했다. 매 요청 검증되는 토큰은 저장소 조회 없이 서명만으로 검증해야 STATELESS의 이점이 유지된다. 대신 무효화할 수 없으니 수명을 짧게 둔다. 서버 상태(로그아웃, 회원 탈퇴등)는 토큰을 새로 발급하는 시점에만 확인한다. 이렇게 하면 저장소 조회 빈도를 낮추면서도 통제권을 확보할 수 있다고 판단했다.

두번째 인가 요청 저장소 문제는 두 가지 대안을 검토 했다.

  • 쿠키 값에 HMAC 서명을 붙이는 방식: 변조는 막을 수 있다. 하지만 데이터가 여전히 클라이언트에 있고, 일회용 보장도 쿠키 삭제라는 클라이언트 동작에 의존한다

  • 쿠키에는 랜덤 키만 두고 실제 데이터는 Redis에 두는 방식: 역직렬화 대상이 서버가 직접 기록한 데이터로 한정된다. Redis의 원자적 명령으로 일회용을 서버가 강제할 수 있다.
    • HMAC 서명 방식은 여전히 보안 취약점이 있고 Refresh Token 저장소로 Redis를 사용하게 되면 추가 인프라 부담도 없었기 때문에, Redis 방식을 선택했다.

    구현
    • AccessToken : 30분 수명. Authorization 헤더로 전송하고, 서명만으로 검증한다. token_type으로 Refresh Token과 용도를 구분하도록 하였다.

    • RefreshToken : 14일 수명. 재발급, 로그아웃시 프론트에서 /auth 패스로 api 요청해 응답 값으로 access token을 전달 받도록 구현하였다. access token 발급시 DB에서 회원의 현재 역할과 상태를 다시 읽어서 발급한다.

    • 인가 요청 저장소: 인가 요청은 Reids에 3분 TTL로 저장하고 쿠키에는 UUID 기반의 키만 담는다. 로그인 실패 시에는 쿠키와 Reids값을 정리한다.

    결과세션 없이 동작하는 STATELESS 구조를 유지하면서, 세션이 제공하던 보안 기능을 각각의 목적에 맞는 방식으로 대체했다.
    • 클라이언트 입력의 역직렬화 경로 제거: 역직렬화 대상이 서버가 직접 기록한 Redis 데이터로 한정되어, 조작된 쿠키를 통한 원격 코드 실행 가능성을 없앴다.

    • 로그인 CSRF 방어 유지: 쿠키의 랜덤 키가 인가 요청을 로그인을 시작한 브라우저에 묶고, state 검증과 함께 콜백 위조를 차단한다

    • STATELESS를 유지하면서 통제권 확보: API 요청마다 저장소를 조회하지 않으면서도, 로그아웃과 강제 만료 시 Redis 삭제로 재발급을 즉시 차단할 수 있게 되었다.
